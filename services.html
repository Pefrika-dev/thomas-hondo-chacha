02How I work

A clear process. No guesswork.

Good outcomes come from a considered sequence, not a sprint towards the first visual idea. Here is how a project typically moves from conversation to handover.

Start a conversation
  1. 01

    Understand the problem

    We start with your goals, audience and constraints. Before building, we get clear on the problem that actually needs solving.

  2. 02

    Define the requirements

    We map the content, features and what the first version needs to do. The scope becomes explicit, so expectations stay aligned.

  3. 03

    Design the experience

    I shape the layout and interface flow, then test decisions around structure, language and interaction before development.

  4. 04

    Develop the solution

    I build with clean HTML, CSS and JavaScript, paying attention to responsive behaviour, accessibility and performance.

  5. 05

    Test and refine

    I check the work across screen sizes, exercise forms and links, and fix what can be clearer, faster or more resilient.

  6. 06

    Prepare the handover

    You receive the code, supporting notes and what is needed to run and maintain the site with confidence.

Scope and pricing
